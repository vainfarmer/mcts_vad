## Lessons learned (failure modes confirmed/refuted)

- **FM5 confirmed for the SIXTH consecutive loop — and the failure link is now fully characterized: code-side gates cannot enforce what the launcher does not request.** v102 implemented every mandate the v98-v101 autopsies demanded (gate in the metric-extraction path, persisted COMMAND.txt, fresh-dir refusal, pre-launch argv assertion) and the failure still recurred at launch, because the M5 assertion is opt-in (`VAD_REQUIRE_FLAGS` env var) and the launching agent neither set it nor launched via the persisted flag-verified COMMAND.txt. Process rule going forward: the launcher-side assertion must be MANDATORY and NON-OPT-IN — the orchestrator/runner must (a) generate the launch command only from a template that interpolates the loop's flag, (b) export the require-flags variable as part of the launch environment itself, and (c) treat a missing flag string in the final command as a hard abort before any VLM spend. A gate the launcher can silently bypass is documentation, not a gate.
- **The 0.16155 "best" is now confirmed seven times over as a directed-scan draw, and the wrong-location bucket remains unaddressed in vivo.** v97 FCCS, v99 ECE, v100 EUBC, v101 BRP, and now v102 HZG-FC all carry plausible mechanism evidence (sim or literature) and zero live measurements; the full-run spread across six flag-off recordings (0.139-0.162) is the empirical VLM noise band any future flag-ON run must beat by margin, not by point estimate.
- **The pre-registered adjudication protocol worked as designed.** Because 0.173/0.145 keep/revert bands were fixed before any spend, the REVERT call was unambiguous even with the activation failure (0.15861 < 0.173), and the cheap artifact audit (grep [HZG] + COMMAND.txt inspection) detected the sixth FM5 in minutes — the M4 persistence mandate's detective value confirmed again.
- **FM1/FM2/FM3/FM4 remain refuted only by construction, never in vivo.** The cascade's safety arguments (boundary curve independence, frozen count/rank machinery, temp=0 binary perceptual verdicts, single-decision inclusion) were verified at code level by C and D1, but no live [HZG] line exists to validate the density mechanism's core premise (that 8-frame 0.75s-spacing forced-choice verification converts mid-ranked true segments). The T*/Zoom-Zero literature premise and the 0.841 keyframe-coverage finding keep the mechanism worth one more attempt — but only after the launcher-side flag enforcement is fixed, which is now the single highest-value process change in the session.
