## 1. Mechanism and motivation (closures respected)

MCS = **pointwise max-over-13-categories CLIP curve driving the BUE/CBT boundary operators**: committed BUE (extension) and CBT (tightening) both operate along the *resolved category*'s per-frame CLIP curve; if the resolved category is wrong (or the event reads stronger on another category's curve), the boundary operators follow the wrong signal. MCS swaps both operators' curve to `maxcat(t) = max_c curve_c(t)` over all 13 categories. Deterministic post-VLM (reads only cached `clip_features` via `get_category_scores`; zero new VLM/CLIP calls), count-frozen, conf-frozen, order-frozen (BUE/CBT only write t_start/t_end). CBT-RECAL per-category caps are still looked up by the RESOLVED category in both arms — only the curve changes.

Respected closures:
- **Candidate-relocation family closed (CGR/CCR v164–v169)** — MCS relocates no candidates; it changes which curve the *committed* operators read. Detection set, count, confidence and order are untouched.
- **CNV veto family closed on harm (v171/v172)** — MCS never zeroes confidence and never removes a detection.
- Not per-video normalization (destroys level) and not within-video confidence re-rank — no conf writes at all.
- **v192–v195 train-localization/research no-gos untouched** — MCS needs no train labels; curves come from the same cached CLIP features the committed pipeline already computes.
- v196 VLC (VOID) and v197 DSV (VOID) untouched — MCS is a boundary-signal swap, orthogonal to confidence calibration/verification.
