## 2. The mechanism — TCP, prompt-side ONLY

When `tcp_prompt` is ON, `scan_segment` appends the pre-registered block (module-level constant `anomaly_discovery.TCP_PROMPT_BLOCK`, single source of truth) immediately BEFORE the "Respond ONLY in JSON format" line; context_prompt and everything else unchanged. Verbatim (anomaly_discovery.py L31-34):

```
Temporal reasoning instructions:
- The frames are shown in time order and span the whole segment uniformly.
- A real anomaly may be BRIEF (1-3 seconds) and occupy only a few frames in the middle of the clip. Do NOT average the clip: judge by the single most anomalous moment you can find.
- Compare the early frames against the later frames: note any sudden change (impact, fall, crowd scatter, smoke or flame onset, concealment motion). A change that starts and ends inside the clip still counts fully.
```

Same frames, same call count, same directed path, same JSON schema (is_anomalous/confidence/description) — ONLY prompt text changes. Zero latency cost by construction. Not a banned family (not an abs-conf gate, not merge/batch, not scan-density).

Flag-off byte-identity: when OFF the `{tcp_block}` placeholder expands to "" so the prompt is bit-identical to the committed prompt (anomaly_discovery.py L397: `tcp_block = (TCP_PROMPT_BLOCK + "\n\n") if self.tcp_prompt else ""`).
