# v3 API 错误补偿

批量评测默认启用两层补偿，无需修改原有启动指令。

1. 单次逻辑 API 请求最多执行 3 次，失败后随机等待 2–8 秒再试。
2. 首轮所有视频结束后，可恢复错误导致的失败视频随机等待 5–15 秒，重新完整诊断一次。成功视频不重跑。

可恢复错误包括连接错误、超时、HTTP 408/409/429 和 5xx。认证、权限、模型不存在等错误（如 401/403/404）不自动重试；普通代码错误也不重试。次数耗尽后仍失败的批次不会计算不完整的评测指标。

检测和分类客户端共享最多 4 个正在执行的 API 请求；视频并发仍由 `--concurrency` 控制，例如设为 2。等待 API 重试时释放请求并发槽。同视频并行片段中一个失败时，先取消并回收其余任务，避免旧请求与重新诊断重叠。SDK 自带重试关闭，避免重试次数叠加。

MCTS 或分类模块即使内部捕获了已耗尽重试的 API 错误，也不能将该视频记为成功。MCTS 自身的候选时间预算仍有效；预算取消不属于 API 错误，不触发该补偿机制。

## 参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--api_retry_attempts` | 3 | 包含首次调用的总尝试次数；1 表示禁用请求重试 |
| `--api_retry_min_seconds` | 2 | 请求重试等待下限 |
| `--api_retry_max_seconds` | 8 | 请求重试等待上限 |
| `--api_concurrency` | 4 | 检测/分类共享的 API 并发上限 |
| `--api_timeout_seconds` | 60 | HTTP 读写等操作超时设置，并非整次诊断总时限 |
| `--api_connect_timeout_seconds` | 15 | HTTP 连接超时 |
| `--video_retry_rounds` | 1 | 批次末尾额外诊断轮数；0 表示禁用 |
| `--video_retry_min_seconds` | 5 | 视频重新诊断等待下限 |
| `--video_retry_max_seconds` | 15 | 视频重新诊断等待上限 |

随机等待范围要求 `0 <= min <= max <= 60` 秒。最后三项仅适用于 `batch_evaluate.py`；`run.py` 单视频入口支持请求级重试。

## 日志和用量

- `run.log`：`[API-RETRY]` 记录模型、失败次数、异常类型、HTTP 状态及等待秒数；`[VIDEO-RETRY]` 记录重新诊断的视频和次数。
- `metadata/video_attempts_<运行标识>.jsonl`：逐次诊断状态、耗时、错误类型及是否可重试。
- `metadata/run_status.json`：最终成功/失败数、总诊断尝试数及补偿成功视频数。
- 视频结果中的 `diagnosis_attempt`：本次批次内第几次诊断成功。`token_usage` 是成功的这一次诊断用量，`token_usage_all_attempts` 合计同一批次执行中该视频所有诊断尝试。
- 现有逐请求及批次 token 日志保留每次实际 API 调用。接口未返回 usage 的失败请求标记用量未知，不假设其计费为零。

完整重新诊断可能再次调用此前已成功的请求，增加耗时和 token。累计字段仅覆盖本次批次执行，跨进程的手动续跑仍需合并各运行用量日志。

代码与重试配置纳入实验指纹。本次升级后请使用新的实验输出目录（例如 v215），不要直接续写旧版 v214 目录。

## 验证

在 common 环境运行：

```powershell
python -m pytest tests/test_llm_usage.py vad_v3/video_anomaly_detection/tests -q
```

测试覆盖瞬时错误重试、永久错误不重试、取消传播、失败片段任务回收、批末仅重跑可恢复失败视频、重试次数上限及多次诊断 token 累计。测试使用模拟 API，不发出付费请求。
