# MCTS 接受协议优化（boundary-v3-2）

目标是减少有充分依据的提案被提示词歧义或引用错误拒绝；接受率本身不是精度指标，不能通过删除完整性或证据检查来获得。

## 已实现

1. **节点与最终比较使用相同的完整性定义。** 必须保留证据中同一事件的可见开始、关键动作与可见结束；不要求保留无关背景。原候选本身也可能不完整，不能将原区间等同于真实事件边界。看不清时仍返回 unknown/不完整。
2. **显式标明 reference/proposal 对应哪个 A/B。** 所有布尔字段都评价 proposal，避免 `complete_without_loss` 被解释为“获胜区间是否完整”。最终仍须同时满足：选择新提案、同一事件、完整无损、删除区域无目标事件、新增区域与同一事件一致。
3. **逐段建立变更区域映射。** 请求中的 `changed_regions` 含区域 ID、removed/added 类型、半开区间秒数及 `eligible_image_indices`。索引是本次请求的零基图片编号，不是全视频帧号；区间右端点的图不属于该区域。
4. **字段规格代替填好答案的 JSON 示例。** 不再展示 true/false、固定置信度和空引用数组作为默认答案。明确“引用为空”不表示“该区域没有异常”：判断无异常也需要引用看过的证据。
5. **一次受限的引用纠正。** 只有全部语义条件已经通过，且引用有问题时才触发；保留原图、原提案和全部语义结论，仅纠正引用。纠正若改变 winner 或布尔结论则拒绝。仍受原来的每候选/每视频请求预算与搜索超时约束，不额外扩充预算；没有余额就回退。非法 JSON/字段类型仍按原规则回退，不对 API 错误或语义拒绝无限重试。
6. **全部失败项可见。** JSON 新增 `changed_regions`、`pairwise_attempts`、`semantic_failures`、`citation_failures`、`rejection_reasons`。节点评价也保存结构化 answer。控制台输出 `[MCTS]` 候选开始、结果及视频摘要；原来的 reason 保留作简要原因。
7. **可选外扩动作。** `shrink_expand_shift` 增加左右外扩，使已经过窄的原区间有补全机会。外扩仍受 seed 相对位移、搜索范围、证据覆盖、CLIP 质量和最终比较约束；不等于直接扩大所有候选。

引用验证还要求所引用的每个索引都属于对应 removed/added 区域集合，不能用“引用全部图片”绕过。非空变化区域每段至少一张有效引用；没有变化的类型必须为空。

## 配置

默认动作仍为 `shrink`，保留旧搜索空间用于控制变量。新提示词自动生效；新增 `citation_repair_attempts=1`（允许0或1）默认启用预算内纠正。

```text
--mcts_mode refine --mcts_trace
--mcts_citation_repair_attempts 1
```

仅验证提示词时保持动作不变。单独验证补全能力时再添加：

```text
--mcts_action_set shrink_expand_shift
```

V1/V2 不受影响，V3 的 off 仍不执行 MCTS。shadow 和配对评测仍保留。修改了协议和源码，后续实验必须使用新的输出目录，不能追加到 v212 的旧 manifest。

## 如何验证效果

本次用模拟 API 验证了：双侧变更引用、A/B 交换、拒绝原因同时存在、一次纠正成功、纠正仍缺证据、纠正篡改语义、禁用纠正、请求预算、外扩合法性，以及只收缩会切断而外扩可保留事件的场景。没有重新运行付费全批次，尚无实际通过率或 mAP 改善结论。

后续开发集比较应固定采样、CLIP 配置和模型，分别测试提示词变化与动作空间变化；报告搜索数、语义通过数、引用失败数、纠正次数、最终接受数、完整尾流程 mAP 和 token。通过率提高但 mAP 下降不能判定优化成功。v212 已参与问题诊断，不能把反复在这14个视频上的调参结果当成独立泛化验证。


## 可选宽松搜索配置

`run_relaxed_search.ps1` 提供独立入口，未修改原保守默认值，也未自动运行新的付费测试。

| 项目 | 原配置 | 宽松入口 |
|---|---|---|
| 触发条件 | contrast_raw < 0.15 | all_valid，取消对比阈值 |
| 动作 | shrink | shrink_expand_shift |
| 单请求图片上限 | 16 | 32 |
| 边界最近证据距离上限 | 1秒 | 1.5秒 |
| 区间证据最大间隔 | 2秒 | 3秒 |
| 每视频候选数上限 | 2 | 4 |
| 每视频逻辑请求上限 | 20 | 40 |
| 每候选逻辑请求上限 | 10 | 10 |

all_valid仍按对比值优先排序，受候选数和请求预算限制，不保证每个候选都搜索。边界和区间覆盖检查仍存在，只适度放宽时间分辨率；过稀证据仍回退。最终的同一事件、完整性、CLIP质量下降保护、有效变更区域引用和A/B选择条件不变。

代价是可能增加请求、图像token和时间；证据间隔变大也可能漏掉很短的动作。该配置用于检验搜索覆盖及扩展动作是否有帮助，不能预先保证接受率或mAP提高。未来若测试这组组合配置，不能将变化归因于某一个参数。

环境中设置 DASHSCOPE_API_KEY 后，从项目根目录执行（输出使用新目录）：

```powershell
.\vad_v3\run_relaxed_search.ps1 -OutputDir .\vad_v3\experiments\v214\results
```


## 相对不退步接受模式（boundary-v3-3）

新增 `--mcts_acceptance_policy relative_nonloss`，宽松入口脚本已启用；普通CLI仍默认strict，旧实验文件不修改。本节取代上文对宽松入口“最终完整性条件不变”的描述。

- strict：节点必须complete且没有event_cut；最终必须选择新提案，并complete_without_loss=true。
- relative_nonloss：允许新旧节点都partial，但不允许complete退化为partial，也不允许新增event_cut。最终可选择新提案或tie，不强制绝对完整；新增必填布尔 `preserves_reference_content=true`，要求明确保留原区间可见目标内容。字段缺失/类型错误或判断不确定均拒绝。
- 两种模式都要求同一事件、删除区域无目标内容、新增区域与事件一致、有效逐段图像引用和CLIP质量下降保护。格式解析、预算和超时不取消。引用纠正也不能更改新增的内容保留判断。

A/B是同一组证据下的原边界/新边界比较，不是两个独立模型或两次完整视频推理。其作用是独立检查提案，而不是只相信搜索奖励。相对模式放宽了“必须明确胜出”和“必须绝对完整”，仍保留A/B判断是否退步。

本次仅通过模拟API及回归测试，尚未重新跑真实视频。原区间不完整时保留已有内容不意味着已经完整定位事件；tie被接受也不保证提升mAP，应继续配对评测。
