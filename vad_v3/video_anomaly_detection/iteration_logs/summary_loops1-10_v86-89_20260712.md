# Agent Team Loops 1-10 Summary (v86-v89 Session)
## Date: 2026-07-12
## Pipeline: video_anomaly_detection (UCF-Crime)
## Target: mAP >= 0.20 (revised down from 0.50), minimize per-video latency

## Executive Summary
This session began by discovering a chain of 5 failed experiments (V80-V85b,
archived) from prior work, all attempting to leverage a genuinely-improved MIL
model via curve-shape-modifying changes (fusion weight, candidate pooling,
confidence re-ranking) - all regressed mAP from 0.149 to 0.04-0.11. The
pipeline was reverted to the clean, proven V51 baseline and a fresh 10-loop
sequence (v86-v89) was run with a hard constraint: only attempt changes that
are ISOLATED from the CLIP+MIL fused curve shape used in half-max boundary
detection.

**Final result: mAP=0.1494 (V89), matching V51's historical best (0.1492).**
**Target of mAP>=0.20 was NOT achieved.**

## What Was Tried This Session (v86-v89)

### V86: Soft-NMS + Diverse-Perspective Self-Consistency
- Soft-NMS (Bodla et al. ICCV 2017): decay overlapping detections' confidence
  by Gaussian tIoU instead of hard removal. Theoretically "fully isolated"
  from CLIP curve shape (Agent A research, high confidence).
- Diverse-perspective self-consistency: 3 VLM category tie-break calls now
  use different analytical angles (scene/action/outcome) instead of 3
  identical prompts (Agent B research).
- Smoke test (14 videos): mAP=0.1283, no red flags, proceeded to full eval.
- **Full eval (65 videos): mAP=0.0961 - REGRESSION.**

### Root Cause of V86 Regression (important general lesson)
Reading evaluate.py's `compute_temporal_map()` revealed standard GREEDY
matching: predictions sorted by confidence, each ground-truth segment
matchable only ONCE. Soft-NMS's permissive survival threshold let 2-3
near-duplicate detections survive per true event; only the highest-confidence
one becomes a true positive under greedy matching, the REST become FALSE
POSITIVES, directly hurting precision/AP.

**This contradicts the research's "fully isolated, safe" classification.**
Soft-NMS WAS correctly isolated from the CLIP/MIL curve shape (as claimed),
but it was NOT isolated from the mAP EVALUATION PROTOCOL. Being isolated from
the detection ALGORITHM doesn't guarantee being isolated from the evaluation
METRIC - both must be checked. This is a new, generalizable lesson beyond
this project's prior "curve-shape" lesson.

### V89: Revert to Hard-NMS, Keep Diverse Prompts
- Reverted Soft-NMS to the proven Hard-NMS (temporal_nms).
- Kept diverse-perspective self-consistency (orthogonal to segment count/NMS,
  only affects category LABEL assignment on already-finalized detections).
- **Full eval (65 videos): mAP=0.1494** - matches V51's 0.1492 almost exactly.
- Per-threshold breakdown (AP@0.7=0.0909) matches a PREVIOUSLY-DOCUMENTED
  pure-noise comparison (V51 vs V69 in a prior session, identical code,
  different VLM API run also produced AP@0.7=0.0909 vs V51's 0.0331) -
  strongly suggesting V89's profile change is within VLM stochasticity,
  not a proven effect of diverse-perspective prompting.
- **Conclusion: NEUTRAL result.** Confirmed non-regressing, zero extra cost,
  theoretically motivated - kept as a reasonable default, but not proven to
  improve mAP on this noisy benchmark.

## Research Findings That Were REJECTED Before Implementation (saved time/risk)

### MIL v6 Early-Exit Pre-Filtering (Loop 4) - Empirically Rejected
Literature suggested video-level MIL pre-filtering (skip expensive CLIP+VLM
pipeline for videos MIL confidently scores as Normal) is "provably mAP-
neutral" since it's a binary process/skip gate. Before implementing, checked
actual MIL v1 score distributions on the test set: found abnormal videos have
a long left tail (5% of genuinely abnormal videos score below 0.197 max),
meaning ANY threshold catching 85-90% of normal videos would ALSO false-
negative 3-6% of true anomalies - directly hurting recall/mAP, contradicting
the "provably neutral" framing. REJECTED without implementation, saving
significant risk.

### CoreML Conversion for Latency (Loop 6) - Deferred, Not Rejected
Highest-impact latency idea (3-4x CLIP encoding speedup, ~13fps -> ~40-55fps)
but touches the most critical, most extensively-validated code path (CLIP
encoding feeds both candidate generation and boundary detection). Given this
project's repeated experience that "safe-seeming" CLIP-path changes have
unexpected regressions (V72 re-centering, V78 confusion-negatives), and the
4-8 hour implementation+validation cost, this was DEFERRED to a future
session with dedicated time for careful numerical-equivalence validation,
rather than attempted blind within this session's budget.

### Already-Implemented Latency Optimizations (discovered, not new work)
Research identified several "quick win" latency ideas that turned out to
ALREADY be implemented in the codebase: persistent VLM API connection
(AsyncOpenAI client instantiated once per batch run), concurrent VLM calls
(asyncio.gather used in both _directed_llm_scan and _ensemble_classify),
and cached CLIP text embeddings (computed once in AnomalyExpert.__init__).

## Cumulative Project History (both sessions combined)
Approximately 45 distinct pipeline versions (V51 through V89, spanning 2
sessions) have now been tried, covering boundary detection algorithms (7
variants), candidate generation (5 variants), MIL retraining (5 attempts:
v2/v3/v4/v6, all with different loss formulations), confidence re-ranking (3
variants), post-processing (Soft-NMS), and category classification (diverse
prompting). ALL either regressed or produced results within the documented
±0.03 VLM-stochasticity noise band around 0.14-0.15 mAP.

## Why mAP>=0.20 Was Not Achieved
1. **Structural ceiling confirmed yet again**: 0.14-0.15 mAP appears to be a
   genuine ceiling for this zero-shot CLIP+VLM architecture on UCF-Crime,
   not a matter of insufficient tuning effort.
2. **The half-max boundary detection algorithm is uniquely sensitive**: any
   change that modifies the shape of the fused score curve (fusion weights,
   candidate pool composition) regresses performance regardless of whether
   the INPUT signal is individually "better" by component-level metrics.
3. **The mAP evaluation protocol (greedy single-match) adds another
   constraint**: post-processing changes must also respect this protocol's
   assumptions (one detection per GT segment gets credit), not just avoid
   touching the detection curve.
4. **Literature confirms this is near the frontier**: published SOTA trained
   WTAL methods (not zero-shot) report only 6-13% mAP@0.1-0.5 on UCF-Crime
   using FULL model training with real temporal labels - our 14-15% at the
   harder 0.3/0.5/0.7 thresholds, achieved zero-shot, is genuinely competitive.

## Recommendation for Future Work
Reaching mAP=0.20+ likely requires either:
(a) Real temporal training labels (UCA dataset, CVPR 2024) + genuine
    supervised training of a temporal localization head - a materially larger
    undertaking than any change attempted across 45 versions so far, or
(b) Careful, rigorous CoreML/MLX latency optimization (deferred this session)
    to at least achieve the "minimize latency" goal even if mAP plateaus, or
(c) Accepting the current ~0.15 mAP as the practical ceiling for this
    architecture and shifting focus to robustness/latency/production-
    readiness rather than further mAP chasing.
