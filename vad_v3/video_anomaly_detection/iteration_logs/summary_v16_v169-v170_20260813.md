## 1. THE INSTRUMENT — single-run DUAL-ARM, and why it is sound

VERIFIED code structure (pipeline.py): CGR (~L1888) -> CCR (~L1917, OFF) -> BUE (~L1925) -> CBT (~L1940).
Every one of these runs **AFTER all VLM calls**, reading only (a) cached per-frame motion energy and
(b) the cached CLIP category curve. They are **deterministic post-processing** over a frozen detection
list. Therefore both A/B arms can be produced *inside one eval run*:

- **arm-OFF** = BUE+CBT applied to a `copy.deepcopy` of the **pre-CGR** list = exactly what the
  committed pipeline would have emitted.
- **arm-ON**  = CGR, then BUE+CBT = **the run's real final output** (cross-checked: the run's own
  evaluator reports mAP 0.09743219, byte-identical to the bootstrap's NEW arm — the arm-ON is not a
  reconstruction, it *is* the run).

Same videos, same VLM sampling, same detection count => an **EXACT PAIRED** contrast with **zero
cross-run VLM noise**. The arms differ by exactly ONE function call. Two separate runs would have
re-sampled the VLM and reintroduced precisely the noise that left v165 (P=0.780) and the offline CGR
estimate (P=0.886) inconclusive.

**Mutation hazard — handled and proven.** `_cgr_motion_relocate`, `_bue_boundary_union_extension` and
`_cbt_category_boundary_tighten` all rewrite `a["t_start"]`/`a["t_end"]` **IN PLACE**. Sharing dicts
between arms would corrupt both *silently*. Guard (pipeline.py L1868-1885, comment marks the deepcopy
as load-bearing, not stylistic): the arm-OFF base is `copy.deepcopy(final_anomalies)` taken **before**
CGR, and the arm-OFF replay then runs on a **further deepcopy of that base**, so the arms share **no
dict object**. Independence proof used: (i) code read confirming two nested deepcopies;
(ii) count/identity check on the produced JSONs — 134 arm-ON detections vs 134 index-aligned arm-OFF
rows across 88/88 videos, **0 length mismatches**; (iii) 30 rows differ between arms and 104 are
identical, i.e. the arms are neither aliased (which would give 0 differences) nor desynchronised.

**Flag hygiene (hard constraints).** `cgr_enabled=False`, `cgr_ab_diag=False` by default; the diag
block is gated on `cgr_ab_diag AND cgr_enabled`, so flag-off is byte-identical to the committed
pipeline. CLI present in **both** entrypoints (`run.py` L252/L263, `batch_evaluate.py` L343/L354, both
with `set_defaults(...=False)`). Eval ran `--concurrency 2`, `--categories` baked in (num_videos=88
confirmed in `evaluation_report.json`, so the v14 harness bug did not recur).

## 1b. WHY v15's FIGURE WAS INFLATED (the mistake this session corrects)

v15 judged CGR with `--paired-json pre_cgr_boundaries` and reported **+0.06105**. `pre_cgr_boundaries`
is snapshotted **PRE-BUE**, so the "arm-OFF" it reconstructs is a *pre-refinement* window list. The
measured delta therefore bundled the **committed BUE+CBT gains** into CGR's credit. It was never a
CGR-only number, and v15's promotion of CGR-M to default-ON on that basis was wrong.

The follow-up offline reconstruction (pre_bue vs pre_cgr, both pre-BUE) isolated CGR at **+0.01919,
P=0.886, CI90[-0.005,+0.051]** — directionally positive but under the bar, and structurally **unable**
to see the interaction that matters: after CGR moves a window, BUE grows outward from the **new**
position and CBT clamps against a **different** region of the category curve. **FM6 realized:** the
offline +0.01919 did **not** transfer; end-to-end the sign flips to **-0.00487**.

## 3b. HONEST CAVEATS (both directions)

1. **The absolute-floor gate line is not evidence against CGR.** The tool printed
   `mAP >= floor 0.15132: False (0.09743)`, but **arm-OFF is also 0.10231 < 0.15132** — both arms fail
   that floor, so it does not discriminate between them. This run simply drew a below-average VLM
   sample relative to the committed 0.11806 hard-88 baseline. That is exactly why the **paired** delta,
   not the absolute, is the valid instrument here. The binding evidence is `delta = -0.00487, P = 0.224`.
2. **Power.** With n=88 the CI half-width (~0.018) is still ~3.7x the 0.008 gate, so this run rules IN
   harm only weakly. But it cannot rescue CGR either: a +0.008 effect sits at the far edge of the
   interval while the point estimate is **negative**. This is "no evidence of benefit, weak evidence of
   harm" — not merely an underpowered null.
3. **Do not cherry-pick RoadAccidents.** Its +0.0293 rests on **4 relocated windows in 23 videos**, and
   the same run shows 11 relocations costing more in Shoplifting. A RoadAccidents-only CGR variant
   would need its **own** pre-registered test; treating this subgroup as a win would repeat exactly the
   over-optimism that produced the v15 verdict.
