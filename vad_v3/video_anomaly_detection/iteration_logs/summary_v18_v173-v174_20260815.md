## 1. THE CODE-EXACT ROOT CAUSE AND THE OFFLINE COVERAGE ARITHMETIC

Root cause (verified against source):
- `_sample_keyframes` (anomaly_discovery.py L45-56) returns ALL ~12 ordered frames of a 6s
  @2fps segment (SemanticFrameSampler target K=18 >= 12; semantic dedup only shrinks the
  pre-truncation pool).
- `_comparative_call` (anomaly_discovery.py L110-113) then TRUNCATES to
  `keyframes[:keyframes_per_segment]` — the FIRST 2 frames (t+0.0s, t+0.5s), or the FIRST 1
  under the >60-segment long-video rule. The VLM therefore sees at best the leading ~0.5s of
  every 6s segment it judges.

Offline coverage arithmetic (pre-registered, measured before any live run):
- Committed first-k truncation: >= 1 keyframe inside the GT interval in only **36/44** hard-cat
  videos. The 8 GT-invisible videos: RoadAccidents009/017/021/121/122/131, Shoplifting017/037.
- KFD-U k=2 spread {t_start, t_start+3.0s}: **43/44**.
- Placement ablation (pre-registered offline, not to be substituted): {t,t+3.0s} 43/44 >
  {t+2,t+4} 41/44 > {t+1.5,t+4.5} 40/44 > {t+1,t+5} 38/44 > linspace-to-edges 37/44.
- k=3 fallback {t, t+2.5, t+5}: 44/44 offline, +50% scan tokens (batch geometry 8x3) —
  held in reserve, never used.

The fix as implemented (flag-gated): when `kfd_uniform_keyframes` is ON, `_kfd_spread_select`
replaces the first-k truncation with the deterministic uniform spread (np.argmin nearest-frame,
first-minimum on ties) over the SAME sampled pool; the >60-segment 1-keyframe rule becomes the
segment MIDPOINT. Same segment grid, same batch sizes (8x2 / 16x1), same 16 frames/call, same
call count, same prompts, same thresholds/merge/top-k — zero latency cost by construction.
Flag OFF = byte-identical first-k truncation path.

## 2. WHY CROSS-RUN, NOT PAIRED — and what that caveat means for the strength of the conclusion

KFD changes the VLM INPUTS (which frames are packed into each comparative call). The arm-OFF
arm therefore cannot be replayed deterministically from one run — there is nothing to restore
from a marker log (contrast v171/v172 CNV, a post-hoc confidence operator where the paired-log
instrument rebuilt arm-OFF exactly). Loop 1 was therefore judged by TWO fresh same-session
runs (committed REF + KFD-ON) with the video-level bootstrap.

The tool's caveat, VERBATIM (results/batch_eval_v173_kfd88/bootstrap_ab.json, mode "cross-run"):

> CAVEAT: cross-run mode still carries VLM run-to-run variance (~+/-0.019 unpaired in this
> ledger) ON TOP of the bootstrap CI. Prefer a paired design when the mechanism is post-hoc.

What this means, stated plainly: the unpaired run-to-run noise band (~+/-0.019) is the SAME
magnitude as the measured point delta (-0.018). So this A/B CANNOT establish that KFD-U is
harmful — the negative point estimate is inside what two re-runs of the SAME config can
produce. What it DOES establish is the ABSENCE of the positive evidence the pre-registered
gate requires: promotion needs delta >= +0.008 with P(delta>0) >= 0.9, and we measured a
negative point estimate whose bootstrap probability of being positive (0.449) is below coin
-flip. Promotion decisions require positive evidence; under cross-run noise this experiment
could only ever ratify a clear win, and there is no win. (Corollary honesty note: the fresh
REF run's 0.11744 vs the committed hard-88 ~0.11806 is itself within the same run-to-run
noise — each run re-samples the VLM.)

## 6. THE DECISION

**DO NOT PROMOTE. KFD-U is MEASURED-CLOSED AS-WIRED.**
- All three Loop-1 gate legs fail (delta -0.01800 < +0.008; P 0.449 < 0.9; abs 0.09945 <

- The closure is honest about strength: cross-run noise (~+/-0.019 unpaired) is the size of
  the measured delta, so this experiment does NOT prove KFD-U harmful. It proves the required
  positive evidence is absent, and it proves (section 4) that the offline coverage gain
  (36 -> 43/44) did NOT convert into detections on the purpose population. FM6 again: offline
  coverage/arithmetic gains do not imply online gain (cf. v159 PMX's offline->online
  inversion). The gate is the online numbers; the online numbers are not there.
- The structural fix STAYS IN THE TREE, default-OFF, flag-off byte-identical — same
  disposition as cgr/ccr/cnv. Evidence that would justify revisiting: a scan-prompt change
  that makes the VLM ACT on mid-segment frames (e.g. the comparative prompt explicitly
  contrasting early vs late frames within a segment, so the newly-visible content enters the
  verdict), or a paired instrument capable of replaying arm-OFF for an input-changing
  mechanism. Re-running the SAME mechanism/prompt again under cross-run noise is not
  justified — it cannot produce a ratifiable signal.
