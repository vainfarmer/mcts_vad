## 1. Mechanism and motivation (closures respected)

VLC is the untested signal variant of the **+0.0518 cross-video confidence-LEVEL oracle** from the v11 ranking diagnostic: mAP ranks detections by confidence globally, so setting each video's confidence LEVEL moves mAP even with intra-video order frozen.

Respected closures:
- **v183 (CLC) closed the MIL-signal variant** of this oracle (hard-88 -0.01253; MIL is blind on exactly the brief-event hard cats, v180). VLC therefore uses a **VLM-read** video-level signal, not the MIL signal — the one level source v183's closure explicitly left open ("any future attempt must use a NON-MIL level signal").
- Not per-video normalization (banned 4: destroys level) and not curve-derived within-video re-rank (banned 1): VLC multiplies every detection of a video by one absolute factor `0.5 + 0.5*v`, preserving intra-video order.
- v192–v195 train-localization/research no-gos are untouched; VLC needs no train labels.

## 2. Implementation facts

- Single switch `--vlc_calib` / `--no_vlc_calib`; dataclass `ScoringConfig.vlc_calib` (config.py:251), `from_args` getattr-default False (config.py:485), `set_defaults(vlc_calib=False)` in run.py:330 and batch_evaluate.py:421. DEFAULT OFF = byte-level old behavior, no extra VLM call, no markers.
- Terminal slot (after CNV/SNH, before DetectionResult return) on genuinely-final `final_anomalies`: for ndet>=1 videos, 16 uniformly sampled frames, ONE video-level detect-client call (qwen-vl-plus, "Does this video contain any abnormal activity..."), robust parse to v∈[0,1] (any failure -> v=0.5 + `[VLC-PARSE-FALLBACK]`), then `conf_new = conf_old * (0.5 + 0.5*v)`. Count-frozen, windows-frozen, order-frozen.
- 0-detection videos SKIP the call but still log `[VLC-VID]` (FM17; unconditional per-video summary, v=NA when no call made).
- Paired adjudication: LOG-based — each calibrated detection emits `[VLC-FIRE] vid=... idx=... cat t=ts-te conf=old->new`; OFF arm rebuilt by `analysis_bootstrap_ab.py --paired-log --marker VLC-FIRE --paired-mode conf` (gating source of record).
- Smoke evidence (2-video on/off smokes): onsmoke 4 `[VLC-FIRE]` lines, offsmoke2 0; both smoke mAP 0.36364; restore-verify harness `/tmp/v196_compare.py` keyed ON-reconstructed vs OFF JSONs.

## 10. Family update — what is now refuted / validated

- **NOT refuted**: the VLM-read video-level calibration signal itself. No valid A/B delta was measured (VOID), so the +0.0518 cross-video LEVEL oracle remains un-captured AND this VLM-read variant remains untested by a valid paired verdict. Observed arm-ON hard-88 mAP 0.13229 (vs the 0.11306 gate line) is suggestive but legally unusable.
- **Validated (process)**: VLC's instrumented sanity is exact — per-detection multiplication `conf*(0.5+0.5*v)` verified to 1e-10 on re-grepped markers; v-distribution diffuse (5x0.0 ... 42x0.9 ... 2x1.0), zero parse fallbacks; cost model confirmed (+1 call per ndet>=1 video, 0-det skip works, 2x v=NA).
- **Refuted (tooling, second occurrence)**: LOG-based paired adjudication via (vid, rounded-window)-keyed marker restore is collision-prone for multi-detection-per-window mechanisms — 134 fires -> 121 unique keys -> M4 VOID, same failure mode as v21 SNH. Any re-arm of VLC (or any conf-marker mechanism) must either emit collision-free keys (vid+idx) in the restore tool pairing contract, or use paired-json mode (v26 phase 3 style) instead of paired-log.
